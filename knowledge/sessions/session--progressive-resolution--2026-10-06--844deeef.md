## Виды документов

Начинаем с четырёх, остальные добавим, когда появится нужда:

| `type` | Файл | Сколько | Назначение |

## Поля

| Поле | Обязательно | Значения | Смысл |
|---|---|---|---|
| `type` | да | `charter`, `navigation`, `roadmap`, `iteration` | вид документа, совпадает с префиксом имени |
| `status` | да | `draft`, `review`, `approved`, `deprecated` | согласован ли документ с оператором |
| `state` | да | `active`, `planned`, `in_progress`, `done`, `deferred`, `dropped`, `superseded` | где находится работа, см. ниже |
| `owner` | да | `operator`, `agent` | кто имеет право менять документ без отдельного разрешения |
| `horizon` | для roadmap, iteration | `near`, `mid`, `far` | допустимое разрешение: `far` означает «не более нескольких строк, не проектировать» |
| `track` | нет | slug | направление проекта, к которому относится документ |
| `created`, `updated` | да | дата | как в vault |
| `review_by` | нет | дата | после неё документ считается непроверенным, пока оператор не подтвердит актуальность |
| `closed` | при `done`, `dropped`, `superseded` | дата | когда работа закончилась |
| `part_of` | нет | список путей | чему принадлежит: итерация части roadmap, roadmap части charter |

| `refs` | нет | список путей | документы vault, на которые опирается или которые породил |

Семантика `state` по видам:

- `charter`, `navigation`: всегда `active`. Это единственные документы, у которых нет «выполнено».
- `roadmap`: `active` или `superseded`.
- `iteration`: `planned` → `in_progress` → `done`, либо `deferred` (отложена с условием возврата в теле), либо `dropped`.

Ответ на твой список: «актуален ли» даёт пара `state` + `review_by`; «выполнен ли / отложен» даёт `state` + `closed`; «куда ссылается, к чему относится» дают `part_of`, `depends_on`, `refs`; даты даны явно.
